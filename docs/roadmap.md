# 32 周内核主线与 6 周全志进阶

主线问题是：**一个用户请求，如何变成 CPU 上的任务、内存中的数据和设备上的工作，又如何返回？** 先建立对象关系，再补机制，最后用真实芯片验证。

每周参考 5–8 小时。第 1 周起在 RK3576 真板积累证据，第 15–19 周引入 K230，第 24–27 周建立可重建的 Buildroot 系统。RK3588 对照保留作选读。

## 阶段依赖

任务与并发是所有后续模块的底座；内存知识支撑 MMU 与 DMA；ARM64 与设备模型共同支撑 RK3576 分析。VFS 和 I/O 帮你理解设备文件与 ioctl 的入口。

可以把芯片数据手册当作长期旁读材料，但在没有地址空间、上下文和资源生命周期概念时，先不追逐每个寄存器。

## 每周节奏

建议分成三次：第一次读概念并写预测（1–2 小时），第二次实验和阅读相关源码（2–3 小时），第三次整理反例并自测（1–2 小时）。卡住超过 30 分钟就记录“预期、实际、命令、报错、版本”，缩小问题后再继续。

每阶段只选一个主实验。拓展题用于加深理解，不作为进入下一阶段的强制门槛。编译耗时、板卡适配和 BSP 差异可能延长周期。

## 四个里程碑

1. **第 7 周：能解释并发。** 独立讲清睡眠、唤醒、调度与锁的区别。
2. **第 14 周：能解释软件路径。** 从 fd 追到等待、缓存与内存对象。
3. **第 23 周：能解释硬件接口。** 连接异常、MMU、IRQ、设备模型和 DMA。
4. **第 32 周：能用证据定位。** 对一个真实问题给出复现、源码链路、时间线与结论边界。

## 主线之后如何深挖

选择一个方向连续投入 8–12 周：调度与实时性、内存与性能、存储文件系统、网络、显示/视频、驱动与电源。每条支线都延续“源码版本 + 可复现实验 + 反例 + 证据”的方法，不以收集资料数量评价学习。
