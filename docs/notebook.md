# 实验记录与答辩模板

把以下模板复制到自己的笔记中。公开提交前检查日志里的凭据、序列号、网络信息与未公开资料。

## 单次实验模板

```markdown
# 实验编号与标题
日期：
当前章节：

## 问题与预测
- 我想验证：
- 预计看到：
- 能推翻假设的现象：

## 环境
- 用户系统与 uname：
- 运行内核与配置：
- 源码 URL / 完整 SHA / 本地改动：
- 板型 / BSP / 固件 / DTB（如涉及）：
- 工具、输入与版本：

## 复现步骤
逐条命令、参数和输入，不省略准备条件。

## 原始证据
输出、trace、日志位置、采样时钟与可能噪声。

## 解释
- 核心对象与生命周期：
- 执行上下文与状态变化：
- 对应源码入口：
- 观测事实 / 源码推断 / 尚未确认：

## 反例
改变哪个条件，结果如何，说明什么。

## 结论边界与下一步
哪些结论可以迁移，哪些只适用于这个版本/平台。
```

## 填好的一份短记录

以下数字来自 [L01 的 Ubuntu 实验](lab-pid.md)。相同的写法也适用于后面的中断、内存和设备实验。

| 笔记栏目 | 本次如何填写 |
| --- | --- |
| 问题与预测 | worker 与 main 的进程号相同。若属于同一线程组，分别打开两个线程的 status 应读到相同的 Tgid。 |
| 输入与观测窗口 | 主线程创建两个 worker，在它们各自休眠的 30 秒内读取线程视图。 |
| 原始证据 | worker-a 打印 `pid=2754 tid=2756`；该次 `ps -L` 的对应行是 `2754 2756 Sl pid_threads`；任务目录中有三个编号。 |
| 能解释的机制 | 程序的 getpid 与 ps 的 PID 列都给出组标识。worker-a 的 TID 用于定位它自己的 task 目录。 |
| 还缺的证据 | 这份原始记录只有组长 status。要直接核对 worker 自己的 Pid 字段，需要在它存活时补读 task/2756/status。 |

**要不要把浮动编号写死在复现命令里？** 笔记保留当次数字；下一次采样的命令用 `$!` 取得新的后台进程号。别人要复现的是组关系，即使得到另一组数字也能对照。

**读到两条时间相邻的日志，能把「A 导致 B」写进结论吗？** 先写「先观察到 A，随后观察到 B」。寻找共同的请求号、线程号或缓冲区，以及代码里实际传递事件的位置。只有时间顺序时，把因果写在假设栏，再设计一次能区分其他解释的对照。

## 每周复盘

写下：本周最重要的三个因果关系、一个被实验推翻的想法、一个还没有证据的问题、下周的一个主实验。把“读了多少页”换成“能解释哪些现象”。

## 最终答辩模板

用 10 分钟说明：问题与复现（2 分钟）、对象与时序（4 分钟）、区分假设的实验（2 分钟）、结论边界与后续工作（2 分钟）。被追问时先区分已验证事实与推断，再回到证据。

完成标记只是提醒。真正的学习记录是你能复现、能解释、能被检验的实验。
