# 从这里开始

这是一条在 RK3576 上学习 Linux 内核、用 K230 对照 ARM64 与 RISC-V、再到全志 SoC 深入板级开发的实验路线。参考周期 **主线 32 周，全志进阶 6 周，每周 5–8 小时**；用验收结果决定进度，日历只用于安排时间。

## 最终希望你能做到什么

面对一次阻塞、卡顿或设备异常，能指出涉及的任务、内存、设备与执行上下文；能找到对应版本的源码，提出假设并设计实验；能把 ARM64 的地址转换、中断与多核机制映射到 RK3576 的实际驱动和硬件资源上。

这代表具备独立分析常见内核问题的基础，不代表读完所有子系统、精通每种 CPU 微架构或完成芯片 RTL 设计。文件系统、网络协议栈、实时内核等都可以在主线完成后单独深挖。

## 你的起点

从第 1 周就使用 RK3576。WSL2 Ubuntu 24.04 用来读源码、交叉编译和保存记录。开发板用已有板厂镜像或适配该板的 Armbian 运行程序。

如果你以前接触过启动、设备树、GPIO 或 I²C，先用阶段验收检查理解程度。能独立解释并复现实验的部分可以加速，不需要机械重学，也不默认已经掌握。

## 第一次读 Linux 命令时看哪里

打开 Ubuntu 终端，试着查「正在接收我输入的这个 shell 是谁」。shell 是解释命令的用户进程。`$$` 由 shell 展开为自己的进程号，`/proc` 是内核把运行状态呈现为文件的接口。在同一个终端运行两行。

```bash
printf 'shell PID = %s\n' "$$"
grep -E '^(Name|Tgid|Pid|Threads):' "/proc/$$/status"
```

假设第一行打印 800，第二行有 `Name: bash`、`Pid: 800` 和 `Threads: 1`。这表示这次查看的是进程 800，它在采样时只有一个线程。接着做 L01，创建两个 worker 后观察新程序的 `Threads` 如何变为 3。两次观察放在一起，就能回答「一个进程能有几个可调度的线程」。

**为什么要在两处写同一个 `$$`？** 这样 `grep` 读的是刚才确认过的 shell。改成 `/proc/self/status` 时，`self` 随打开文件的进程而定，这条命令里打开它的是 `grep`。

**已经在 WSL 做出了 L01，该重做还是往下走？** 先遮住输出，预测某个 worker 的 `Pid` 和 `Tgid`。能解释并核对，就进入 [L02 的阻塞与唤醒](lab-wait.md)；以后在 RK3576 重跑时再补板端记录。
