# 从这里开始

这是一条从 Linux 用户空间走向内核、再走进 ARM64 与 RK3576 芯片的实验路线。参考周期 **32 周，每周 5–8 小时**；用验收结果决定进度，日历只用于安排时间。

## 最终希望你能做到什么

面对一次阻塞、卡顿或设备异常，能指出涉及的任务、内存、设备与执行上下文；能找到对应版本的源码，提出假设并设计实验；能把 ARM64 的地址转换、中断与多核机制映射到 RK3576 的实际驱动和硬件资源上。

这代表具备独立分析常见内核问题的基础，不代表读完所有子系统、精通每种 CPU 微架构或完成芯片 RTL 设计。文件系统、网络协议栈、实时内核等都可以在主线完成后单独深挖。

## 你的起点

从第 1 周开始。当前已经准备了 WSL2 和 Ubuntu 24.04，可以先完成通用 Linux 实验；到架构阶段使用 QEMU ARM64，到设备与芯片阶段再使用 RK3576 开发板。

如果你以前接触过启动、设备树、GPIO 或 I²C，先用阶段验收检查理解程度。能独立解释并复现实验的部分可以加速，不需要机械重学，也不默认已经掌握。

## 今天的 60 分钟

1. 阅读[环境与版本基线](environment.md)，建立实验目录，记录 `uname -a` 和 `uname -m`。
2. 打开[L01 · PID / TID](lab-pid.md)，先写预测，再编译运行线程程序。
3. 把程序输出与 `/proc/PID/task/` 对照，用自己的话解释 PID、TID、TGID。
4. 按[实验记录模板](notebook.md)保存结果。能通过自测后，再标记文档完成。

## 第一周安排

| 学习块 | 时间 | 可检查的产出 |
| --- | --- | --- |
| 环境与目录 | 45 分钟 | 一份版本记录 |
| C 指针、结构体、编译链接复习 | 90 分钟 | 解释一段链表或回调代码 |
| PID / TID 实验 | 60–90 分钟 | 输出、观察命令和解释 |

剩余时间补齐遇到的工具和 C 知识。不要一开始就通读 `sched/core.c`。

## 如何使用这个站点

“学习路线”展示阶段与先后关系；“实验手册”提供操作、预期现象、反例和验收；“平台地图”说明每个环境能够验证什么。搜索支持中文和符号名，例如 `task_struct`、`IOMMU`。

学习完成状态只保存在当前浏览器，可从侧栏导出备份。它是自我检查标记，不会验证你真的做过实验，也不会同步到 GitHub。正式实验记录建议提交到自己的笔记目录。
